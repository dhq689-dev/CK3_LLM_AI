Review of the workflow

The pipeline is sound. A few things will bite later:

Ironman saves are unparseable. Steps 1-6 only work on non-Ironman games. That's fine, but it also means console and mod injection won't cost you more than achievements.
Let the LLM choose from legal moves. Free-form plans ("ally with Y, be aggressive") are hard to translate reliably. Have Python precompute a short menu per ruler (valid war targets with claims or CBs, rulers who could plausibly ally, current truces) and make the LLM return a constrained, schema-validated choice. This also keeps it from hallucinating targets.
Key plans on titles, not character IDs. Rulers die. title:k_france.holder survives succession, and you can attach an expiry date to each plan.
Close the loop through the save. If the injected effects set variables and flags (plan ID, plan start date), your next parse sees what was applied and what happened, and you can feed that back into the next briefing so the LLM has memory of its own plan.
Limit hard actions per cycle. One or two forced actions per ruler per cycle keeps the AI feeling like an AI and stops runaway behaviour.
The best injection design: two layers, soft and hard

The strongest approach isn't just nudging AI personality values. It splits intent into two kinds of lever.

Soft steering (continuous, unreliable on its own):

Character modifiers carrying ai_boldness, ai_energy, ai_greed, ai_vengefulness and so on, plus war-related modifiers like ai_war_chance and ai_war_cooldown. Check exact names against the dump from the script_docs console command.
Pre-define a few tiers (e.g. ck3llm_aggressive_1 to _5) in a hand-written static mod. Python only emits which tier, and the modifier is applied with years = 5 so plans expire without any outside help.

Hard actions (discrete, deterministic): the same effects the game itself uses. Examples are start_war, add_opinion with a custom modifier, add_hook, create_alliance, add_truce, set_designated_heir, and add_pressed_claim. This is where "ally with Y" becomes real: a mutual opinion boost plus the alliance effect, guarded by in-game triggers so illegal moves silently no-op. Soft steering alone rarely produces a specific war or alliance.

How the plan gets into the game

CK3 can't read files at runtime, so the plan has to be baked into script. Your options:

Route	Restart needed?	Robustness	Notes
Generated mod file (Python writes a scripted effect, a static on_action calls it)	Yes	High	Cleanest. Turn-based: save, parse, LLM, write, restart, load
Console effect/run (Python writes commands, you or a keystroke injector runs them)	No	Medium	Near-live. Console is non-Ironman only; I believe run <file> reads from a run/ folder in your user directory, so verify that
Edit the gamestate text and rezip	Reload save	Low	Format-fragile, easy to corrupt. Avoid unless the others fail

My recommendation is the generated-mod route first, since it's deterministic and debuggable. Add the console route later if you want a live loop on autosaves.

Static mod (written once):

# common/on_action/ck3llm.txt
yearly_global_pulse = {
	effect = { ck3llm_apply_plans = yes }
}

Generated by Python each cycle:

# common/scripted_effects/ck3llm_plans.txt
ck3llm_apply_plans = {
	title:k_france.holder ?= {
		if = {
			limit = { NOT = { var:ck3llm_plan_id = 42 } }
			set_variable = { name = ck3llm_plan_id value = 42 }
			add_character_modifier = { modifier = ck3llm_aggressive_4 years = 5 }
			# hard action, guarded so it silently no-ops if illegal
			if = {
				limit = { exists = title:k_england.holder }
				add_opinion = {
					target = title:k_england.holder
					modifier = ck3llm_friendly_opinion
					opinion = 30
				}
			}
		}
	}
}

The ?= scope guard and the plan-ID check make it safe against dead holders and idempotent across yearly pulses.

Practical tips for the prototype
Use debug_log in the effects and watch Documents/Paradox Interactive/Crusader Kings III/logs/error.log to confirm plans actually applied.
Run script_docs once to dump valid effects, triggers and modifiers for your game version, so the translation layer targets real names.
Because plans are applied per yearly pulse, the natural cadence is one LLM cycle every few in-game years (e.g. per autosave), not continuously.
